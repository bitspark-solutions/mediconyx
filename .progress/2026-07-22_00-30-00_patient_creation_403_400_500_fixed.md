# 2026-07-21 — Patient-Creation Bug Chain Fixed (403/400/500)

User (as master, dev stack) hit a 403 creating a patient via the UI (HAR provided). Diagnosis uncovered three stacked bugs:

## Root causes & fixes

1. **403 Forbidden** — the browser held a stale JWT from before the RBAC/permission system. Old tokens without permission claims fail every `[HasPermission]` endpoint. No code fix — log out/in. Verified: fresh master token passes authorization on `POST /api/patient`.
2. **400 on string enums** — UI sends `"gender": "Male"`; API had no `JsonStringEnumConverter` and only accepted numeric enums. **Every form posting a dropdown value was broken.** Fix: registered `JsonStringEnumConverter` globally in `Extensions/ServiceCollectionExtensions.cs` (numeric values still accepted; response DTOs already used strings, so no response-shape change).
3. **500 on date-only inputs** — HTML date inputs post `"2026-07-08"` → `DateTimeKind.Unspecified` → Npgsql rejects for `timestamptz` columns. **Every form posting a date was broken.** Fix: new `Services/Infrastructure/UtcDateTimeJsonConverter.cs` (Unspecified → UTC no-shift, Local → converted), registered alongside the enum converter.

## Verification
- Exact HAR payload now returns **201** (`P-000008` created) with `dateOfBirth: 2026-07-08T00:00:00Z`, `gender: "Male"`.
- Numeric enum + ISO-UTC date payloads still work (backwards compat).
- Both API images rebuilt (dev `mediconyx-api`, `mediconyx-test-api`).
- Regression: **170/171 unit tests pass, 112/112 E2E pass, 0 failures.**

## Lesson / note for future
- When the API "worked in tests but not in the UI," suspect serializer mismatches — the E2E API helpers sent numeric enums and ISO-UTC dates, which is why the suite was green while the UI was broken. E2E form-driven coverage catches this class.
